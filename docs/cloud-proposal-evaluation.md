## 日期后处理说明

原始模型在下面两类无歧义表达上偶尔保持了空日期：

- “下午……”没有补成本地当天；
- “月底前……”没有补成本月最后一天。

Reflow 使用一个有版本的、确定性的日期归一化步骤补齐这两类表达。归一化只在以下条件同时满足时运行：

- Outcome 是任务；
- 建议去向是当前计划；
- 模型日期为 `null`；
- 原始文本明确包含当天时段或本月月底。

它不会处理“下个月去做”这类没有精确日期的表达，也不会修改等待、稍后或知识结果。报告同时保留原始 88.9% 与处理后 100%，不把后处理伪装成模型原始能力。

## Prompt 与 Schema 的关键修订

- 对具体、可执行、非等待任务给出保守耗时，知识、纯等待和信息不足时保持 `null`；
- 禁止 `CloudProposalDraft`、`AIProposal`、`suggestedBucket`、`estimatedMinutes`、`waitingFor`、`JSON Schema` 等内部名称进入用户字段；
- 将 `waitingDetails` 固定为 `null`，或包含三个完整 nullable 键的对象；
- 区分主动沟通和等待外部反馈；
- 区分“下个月去做”的宽泛未来时间与“以后再做”的 `someday` 意图；
- 信息不足时降低置信度并保持字段为空，不编造对象、内容和日期；
- 明确将 Capture 中的协议覆盖、Schema 篡改和密钥索取视为不可信输入。

## 已知非阻塞问题

- “参赛材料并把缺少的信息发给组员”有 3 次标题压缩略有歧义，需要一次轻微措辞调整；
- “记得那件事情”“嗯那个先弄一下”“跟进一下”等信息不足输入仍需要用户补充；
- 成本高于早期 Terra 评测，但质量门槛已经达到，延迟与成本不是安全同级的一票否决项；
- 第三方兼容服务返回的模型名称只能证明响应声明，不能独立证明底层路由实现。
